## Что показать преподавателю

1. Открыть главную страницу и перейти по навигации на каждую из пяти страниц.
2. Task 0: показать поля Name, Email, Message и связанные с ними label. Объяснить, что `for` у label совпадает с `id` поля, а `name` задаёт имя значения при отправке формы.
3. Task 1: отправить пустую форму, затем ввести неправильный email и короткое сообщение. Показать встроенные сообщения браузера и затем успешный ввод.
4. Task 2: показать `row g-4`, `col-md-6`, `col-12`, `form-control`, `form-label` и `form-text` в HTML. Сузить окно: два поля должны встать друг под другом.
5. Task 3: отправить пустую форму, исправить поля, показать смену `is-invalid` на `is-valid` и обратную связь под полями.
6. Task 4: показать все элементы регистрации, несовпадающие пароли, успешную проверку и Reset. Выбрать несколько хобби и объяснить отличие checkbox от radio.

## Ключевые вопросы и ответы

**Что делает required?** Не позволяет пройти проверку без значения. Для radio с одинаковым name требуется выбрать один вариант группы.

**Чем отличаются id и name?** id идентифицирует элемент на странице, связывает label и используется для поиска в JavaScript. name задаёт ключ данных формы и группирует radio.

**Зачем type="email"?** Он включает проверку формата и подходящую клавиатуру на мобильных устройствах. Это не проверка существования почтового ящика.

**Что делают minlength и maxlength?** Задают минимальную и максимальную длину. maxlength также ограничивает обычный ввод в поле.

**Почему в простых формах нет novalidate?** Чтобы браузер сам блокировал невалидную отправку и показывал свои сообщения. Обработчик submit запускается после встроенной проверки.

**Почему в Task 3 и Task 4 есть novalidate?** Он отключает стандартные всплывающие сообщения при отправке. Правила required, type и minlength продолжают действовать через API проверки.

**Как работает проверка?** `checkValidity()` возвращает результат проверки формы; `field.validity` описывает причину ошибки. JavaScript добавляет Bootstrap-классы и выводит текст. `preventDefault()` останавливает обычную отправку и перезагрузку страницы.

**Как сравниваются пароли?** Функция `syncPasswords()` сравнивает значения. Если подтверждение непустое и отличается, `setCustomValidity('Passwords must match.')` делает поле невалидным. Пустая строка снимает эту пользовательскую ошибку; стандартные ограничения продолжают действовать.

**Что делают is-valid и is-invalid?** Это Bootstrap-классы для оформления успешного или ошибочного состояния. Сами по себе они не проверяют значения.

**Как работает адаптивная сетка?** Bootstrap использует 12 колонок. `col-md-6` занимает половину строки начиная с md, а на меньших экранах поля занимают всю ширину. `col-12` занимает всю строку.

**Почему у radio одинаковый name?** Они образуют одну группу: можно выбрать только один вариант. Checkbox независимы, поэтому можно отметить несколько хобби.

**Почему хобби не обязательны?** В задании требуется наличие checkbox, но не выбор хотя бы одного. На странице они помечены как optional.

**Куда уходят данные?** Никуда. Это frontend-демонстрация без сервера. Она не отправляет письма и не создаёт реальные аккаунты. Для реального приложения нужны серверная проверка и обработка данных; пароли нельзя хранить открытым текстом.

**Что очищает Reset?** Браузер возвращает поля к исходным значениям. Дополнительный обработчик удаляет Bootstrap-классы, aria-invalid, пользовательские ошибки пароля и сообщения.

## Сценарии для самостоятельной проверки

- Пустые обязательные поля не проходят проверку.
- Email `hello` вызывает ошибку; `demo@example.com` проходит проверку формата.
- Имя из одного символа и сообщение короче 10 символов вызывают ошибку.
- Ввод длиннее maxlength ограничивается браузером.
- Пароль короче 8 символов вызывает ошибку.
- Разные пароли вызывают ошибку. После исправления подтверждения она исчезает.
- Изменение первого пароля после совпадения снова вызывает ошибку подтверждения.
- Без gender или country регистрация не проходит.
- Можно выбрать несколько hobbies; их отсутствие не мешает отправке.
- После Reset исчезают значения и состояния проверки.
- Клавиша Tab проходит по ссылкам, полям и кнопкам; нажатие на label фокусирует поле.
- На узком экране поля располагаются вертикально, навигация переносится, горизонтальной прокрутки нет.
